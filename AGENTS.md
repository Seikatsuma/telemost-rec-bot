# AGENTS.md — инструкция для ИИ-агента

Ты — ИИ-агент (Claude Code, Codex, Devin, Cursor и т.п.). Пользователь отдал тебе эту папку,
чтобы ты **сам поднял ему Telegram-бота записи встреч Яндекс Телемоста** — такого же, как у автора.
Работай без остановок: спрашивай пользователя только о том, что нельзя получить без него
(ключи и вход в Яндекс). Всё остальное сделай сам и проверь делом.

## Что получит пользователь

Бот в Telegram: кнопка «🎙 Новая встреча» → ссылка на встречу Телемоста, бот заходит
участником «Запись встречи» и пишет звук. Все вышли → в чат приходят аудио, файл
расшифровки с таймкодами и именами говорящих (имена — по аккаунтам Телемоста, не по голосу)
и короткий конспект. Кнопка «⏸ Пауза» — бот сохранит запись и выйдет, «Продолжить» — вернёт его. Свою ссылку на встречу тоже можно просто прислать — бот зайдёт гостем и напишет «я в ссылке».

## Шаг 0. Куда ставить — выбери с пользователем

Нужен компьютер с Linux, который **включён, когда идёт встреча**. Варианты от лучшего:

| Вариант | Цена | Когда подходит |
|---|---|---|
| У пользователя уже есть VPS/сервер | 0 ₽ сверху | по умолчанию |
| Домашний компьютер/ноутбук, который не выключается | 0 ₽ | встречи днём, компьютер не спит |
| Бесплатный облачный сервер (Oracle Cloud Always Free — ARM VM) | 0 ₽ | нет своего сервера; регистрация с картой (списаний нет) |
| Дешёвый VPS (любой, от ~150 ₽/мес) | ~150 ₽/мес | самый простой платный путь |

Требования к машине: Linux (Ubuntu 22.04/24.04 проверено; другие дистрибутивы — вероятно,
сработает), 2 ядра, **≥1.5–2 ГБ свободной памяти** на время записи (на встречу — свой
Chromium), ~1 ГБ диска + ~1 МБ/мин записи. Windows — через WSL2. macOS — не проверено.

Если ставишь на сервер, где уже живут другие службы — убедись, что свободной памяти хватает
с запасом: браузер на встречу ~0.5–1 ГБ.

## Шаг 1. Ключи — спроси у пользователя списком одним сообщением

| Ключ | Где взять (бесплатно) | Обязателен? |
|---|---|---|
| `BOT_TOKEN` | Telegram → @BotFather → /newbot → придумать имя | **да** |
| `DEEPGRAM_API_KEY` | console.deepgram.com → регистрация по почте (без карты) → API Keys → Create Key. Новому аккаунту — **$200 кредита ≈ 700 часов** расшифровки | желателен; без него расшифровка идёт через Groq |
| `GROQ_API_KEY` | console.groq.com → регистрация → API Keys | желателен: запасной путь расшифровки + конспект |
| `DEEPSEEK_API_KEY` | platform.deepseek.com (платный, копейки) | нет — без него конспект делает Groq |
| Аккаунт Яндекса | есть у любого, кто пользуется Телемостом | нет — только для кнопки «создать встречу»; запись по ссылке работает без входа |

Минимум для запуска: `BOT_TOKEN` + один из `DEEPGRAM_API_KEY`/`GROQ_API_KEY`.
Всё остальное можно добавить потом без переустановки (правка `.env` + перезапуск).

## Шаг 2. Установка

```bash
git clone https://github.com/Seikatsuma/telemost-rec-bot
cd telemost-rec-bot
./install.sh
```

Скрипт сам: проверит Python 3.10+/ffmpeg, создаст venv, скачает Chromium, создаст `.env`,
прогонит локальный стенд записи звука (без Телемоста и Telegram). Если попросит —
один раз `sudo venv/bin/playwright install-deps chromium`, затем `./install.sh` снова.
Нет sudo — поставь системные библиотеки Chromium вручную и укажи папку в `BROWSER_SYSLIBS`.

Впиши полученные ключи в `.env`. Пользователь один — `OWNER_IDS` можно оставить пустым:
бот закрепится за первым, кто напишет /start.

## Шаг 3. Запуск

Быстро проверить: `venv/bin/python bot.py`.
Постоянно: служба `deploy/telemost-rec-bot.service` → `~/.config/systemd/user/`
(поправь пути, если папка не `~/telemost-rec-bot`), `systemctl --user enable --now`,
`loginctl enable-linger "$USER"`. Подробно — README.md «Запуск службой».

## Шаг 4. Проверка делом — обязательна, отчитайся ею

1. `/start` боту — кнопки появились.
2. (если есть Яндекс-аккаунт) `/login` → бот пришлёт QR → сканировать приложением Яндекс
   («Умная камера») → бот подтвердит вход.
3. «🎙 Новая встреча» → ссылка пришла → зайти по ней с телефона/компьютера → сказать пару
   фраз → выйти → через ~30–60 с в чат падают аудио + расшифровка с именем + конспект.
4. Не вышло — смотри `journalctl --user -u telemost-rec-bot -f` или `logs/bot.log`,
   чини и повторяй, пока запись не дойдёт. Есть `/selftest` — встреча с тестовым
   участником без живых людей.

Отчёт пользователю: что работает (создание/заход по ссылке, запись, расшифровка, имена,
конспект) и что нет — списком.

## Границы и честные оговорки — скажи пользователю

- Запись только **звука**, видео нет. Бот виден участникам как «Запись встречи» —
  предупреждай людей, что идёт запись.
- Имена говорящих — из аккаунтов Телемоста: двое за одним микрофоном/аккаунтом = одна
  подпись; гость подписан именем, которое сам ввёл. Это не распознавание голоса.
- Расшифровка и конспект идут на ключи **пользователя** — автору бота они не видны
  и не оплачиваются. Личные данные (профиль Яндекса, записи) живут только на машине
  пользователя.
- Яндекс может обновить Телемост — бот чинится правками `inject.js`/`telemost.py`;
  тесты (`tests/test_timeline.py`, `tests/e2e_fake_telemost.py`) покажут, что сломалось.
- Файлы >50 МБ Telegram-боту не отдать — аудио режется на части автоматически.

## Чего здесь нет и не должно быть

В репозитории нет ключей, токенов, логинов, чужих данных и привязки к чужому серверу.
Всё секретное живёт в `.env` (в `.gitignore`) и в `data/` (профиль Яндекса, записи,
состояние — тоже в `.gitignore`). Не коммить `.env` и `data/` никуда.
